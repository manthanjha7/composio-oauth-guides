# OAuth App Setup Guides for agent builders

**Live:** https://composio-oauth-guides-one.vercel.app

Composio's managed OAuth apps cover prototyping. Production (your own name on the consent screen, your own quota, extra scopes) and every bring-your-own app mean creating a provider OAuth app and getting it approved. That path differs by provider and by setup, and is rarely written down in one place.

For each app, a guide answers:

- Do I need my own OAuth app?
- How hard is approval for **my** setup? It compares setups by scopes, audience and distribution.
- How much of my time does it take, and how long will I wait on the provider? The two are reported separately.
- What do I need first?
- What will block me, and what do I do then?
- Which steps can an agent do (🤖) and which must I do (👤)? Waits on the provider are marked ⏳.

Every claim carries a label: 📘 provider docs, 🟣 Composio docs, 🔎 endpoint check, 💬 reported, ❓ unconfirmed, or 🧪 tested. 🧪 is only for recorded setups; there are none yet.

There are two ways in:

- **A library:** 4 guides researched ahead of time plus 7 generated by the agent.
- **A search box:** type any app or website and the agent researches it live in about 1–2 minutes. That includes apps outside the library and outside Composio's catalog. `/generate?replay=asana` plays back a recorded real run without calling any model.

## Run it

```bash
npm install
cp .env.example .env.local     # add ANTHROPIC_API_KEY for live generation
npm run dev                    # http://localhost:3000
npm test                       # 38 tests, incl. a scripted run of the whole agent loop
```

| Env var | Purpose |
|---|---|
| `ANTHROPIC_API_KEY` | Live generation. The library works without it. |
| `COMPOSIO_API_KEY` | Optional. Search through Composio Search and managed-app status from Composio's toolkit API. Without it the agent uses Anthropic web search and Composio's public docs. |
| `DATABASE_URL` (Postgres, e.g. Neon; used on the live site), `KV_REST_API_URL` + `KV_REST_API_TOKEN` (Upstash) or `BLOB_READ_WRITE_TOKEN` | Storage for generated guides. One is **required on Vercel**: without storage, live generation refuses to run so share links never break. Locally, guides go to `./.data`. |
| `GENERATION_PAUSED=1` | Turns live generation off without removing keys. The site then points to the recorded run. |
| `GENERATE_DAILY_CAP`, `GENERATE_PER_IP_PER_HOUR` | Spend limits. |

Scripts. None of them call a model unless noted.

- `scripts/check-guide.mts <guide.json>`: re-fetches every cited page and checks each quote word for word.
- `scripts/recheck-guides.mts [--write] <guides>`: re-applies the current evidence rules to stored guides.
- `scripts/eval.mts label=<guide.json> …`: scores guides on evidence, structure and per-app must-have facts.
- `scripts/generate.mts "<app>"`: runs the agent from the terminal. **Uses the model.**

## How the agent works (`src/lib/agent/run.ts`)

1. **Composio check:** managed app or bring your own, the toolkit's known errors, Composio's setup guide, and Composio-wide facts such as the redirect proxy for domain verification and the limits of managed apps.
2. **Identify:** names the provider, its website and docs, so a wrong match is obvious. Ambiguous names get a "did you mean".
3. **Research:** official docs against a checklist: limits before approval, pricing, review and timelines, redirect-domain rules, customer-side restrictions, and current vs legacy platform. Up to about 10 page reads and 5 searches. On JavaScript-rendered docs sites it reads the `.md` source, because their HTML drops link text.
4. **Endpoint check (optional):** calls the provider's authorize endpoint with a dummy client and records the reply.
5. **Write:** Claude Sonnet 5.5 writes JSON against a fixed schema, which Zod validates with one repair turn. Research runs on Claude Haiku 5.5 with prompt caching. A run costs about **$0.10–0.20**.
6. **Check the evidence, in code** (`src/lib/evidence.ts`):
   - A docs quote must appear word for word on an official page (the provider's domains or composio.dev).
   - The quote must contain every number in its claim. Version numbers and HTTP codes are ignored.
   - Anything that fails is flagged as ❓ Unconfirmed, or 💬 Reported if the page is real but not official.
   - Unbacked wait times become "Unknown"; unbacked time spans in the summary are shown as warnings.
7. **Save, read back, then link.** Research stops at about 2.5 minutes and writes from what it has rather than timing out. Progress streams to the browser as events.

## Key decisions

| Decision | Choice | Why |
|---|---|---|
| Knowledge source | Live research; the library is saved agent output | Unfamiliar apps must work, and docs change |
| Unit of guidance | A verdict per **setup**, not per app | Gmail is easy for an internal tool and hard for a server-side agent that reads inboxes |
| Time | Your time and provider wait, each with a basis | "An hour of work plus weeks of review" is a different plan from "a week of work" |
| Evidence | A label per claim, with a verbatim quote checked by code | A link alone doesn't prove a claim |
| Attempting setup | Endpoint checks plus planned recorded setups | Logins, 2FA and terms of service make a signup bot fragile |
| Built on | Composio Search, Composio docs and API, Next.js on Vercel | Reuses what Composio already ships, and links to its setup guides |

## Verification (`/verification`)

- **Quote checks:** 361 of 366 quotes across 11 guides match their live source pages word for word.
- **Ledger:** material claims marked confirmed, corrected or unverifiable. Corrections include:
  - My initial plan wrongly said Slack distribution was fine without the Marketplace. Unlisted apps are actually rate-limited.
  - A generated Box guide wrongly said every enterprise admin must authorize the app. The cause was the fetcher; it's fixed and the guide was corrected.
  - The checker produced false alarms of its own, now fixed.
- **Prompt evaluation:** 5 runs ($0.70) scored against the old outputs. Sources roughly doubled, agent-owned steps went from 10–20% to 30–44%, and Gmail now has all 5 must-have facts. The remaining gaps are logged.
- **Reviews:** two independent agents reviewed the plan and one reviewed the code (`docs/reviews.md`).

## Limitations

- **Not reviewed or tested.** No guide is human-reviewed or hands-on tested yet (planned tests are listed on `/verification`).
- **Summaries can overstate.** The summary and setup text aren't evidence-checked the way claims are. One overstatement (Box) was fixed by hand.
- **Logged-in areas.** The agent can't see behind developer-console logins, and review timelines are rarely published. When they're missing, guides say so.
- **Generated guides are thinner** than library guides: 15–31 claims vs 48–81.
- **Rate limiting** on `/api/generate` is per server instance: fine for a demo, not for production.
- **Scale.** 11 guides, not 100. The route to 100 is to batch-run the agent over Composio's 211 bring-your-own toolkits and its most-used managed ones, then review them in order of usage.
