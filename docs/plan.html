1. The problem, in one line

"I want my users to connect App X to my agent. Do I need my own OAuth app, how do I get it created and approved, how long will it take, what will block me, and which parts can an agent do for me?"

What the brief asks for (our checklist, nothing more)

#The brief saysWhere we answer it
B1Look up an app, get a guide they can use and share, know what to do nextFlow A · each guide has a link + a Markdown version for agent builders (§5, §6)
B2How easy or difficult it is to get the OAuth app readyVerdict card, per scenario (scopes × audience × distribution) (§6)
B3Likely time and effort, including the wait for approvalHands-on time vs waiting on review, each with its basis (§6)
B4Requirements and nuances that could affect setupPrerequisites + "what changes your path" + traps (§6)

Where it hurts: steps 1, 3, 6 and 7 differ wildly by provider and depend on the developer's scenario (which scopes, who the users are, how the app is distributed, whether data touches their servers). The developer can't tell if it's 1 hour or months + a paid assessment until they're in it. Steps 2 and 4 (mechanical) are already covered by Composio's existing credential guides.

Product insight from this: difficulty is not a property of the app. It's a property of the developer's scenario. "Gmail" is easy for an internal tool, medium for gmail.send, and hard for a server-side agent that reads inboxes. So every guide starts by asking or assuming the scenario, then gives the verdict for it.

  • One pipeline, two uses: the same agent writes the seed library (then we hand-check it) and the live guides. The library is "agent output a human reviewed." Route to 100: batch-run the same pipeline over Composio's bring-your-own and top managed toolkits, then human-review in priority order.
  • Built on Composio: research tools come through a Composio session; managed status comes from Composio's own API.
  • Structured output: a fixed, small schema (scenario, verdict, time + basis, steps with owner/inputs/done-when, traps, blockers, claims with label + quote + URL + date). Same shape for every app, so 100 guides stay comparable.
  • Fail soft: per-step time limits, sections saved as they finish, a partial guide beats a timeout, and the share link is shown only after the save succeeds.

9. In scope / out of scope

In scope
  • Library page + 3 seed guides (Gmail, Slack, Shopify); Notion as stretch
  • Live "generate a guide" for any app name/URL, incl. apps outside Composio
  • Guide page: scenario, do-I-need-my-own-app, verdict, time + basis, ordered steps with 🤖/👤/⏳, traps, "Stuck?", evidence
  • Share link + Markdown export per guide
  • One recorded agent-driven setup attempt (Slack)
  • Verification ledger with counts
  • README: setup, decisions, limitations, route to 100
Out of scope (deliberately)
  • Building any OAuth / auth flow (Composio has it)
  • Vector database / RAG over scraped docs
  • All 100 guides
  • User accounts, login, history
  • Browser bot in the product
  • Drafting tools (justifications, policies) as product features
  • Forum research on every live run (one capped search at most)
  • Actually getting any app approved; paid accounts; credentials in the repo
  • Auto-refreshing guides (stated as a next step)
